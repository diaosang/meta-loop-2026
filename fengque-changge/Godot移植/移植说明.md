# V15 的移植边界

本轮将「dogot」按 Godot 理解。交付的是可玩的网页版、独立经营规则和 Godot 4 数据接口骨架；并非已经完成 Godot 游戏。当前机器没有 Godot 可执行文件，GDScript 未作引擎运行验证。

## 已拆出的部分

| 文件 | 职责 |
| --- | --- |
| `源代码/simulation/realm-data.json` | 工程、税令、节令、闲暇、阶段目标、时辰等表 |
| `源代码/simulation/realm-core.js` | 无 DOM、无网络、无实时时钟、无隐式随机的纯规则 |
| `源代码/simulation/command.schema.json` | 命令契约，含条件必填项 |
| `源代码/simulation/snapshot.schema.json` | JSON 快照边界 |
| `源代码/simulation/port-vectors.json` | 固定输入、命令、推进到第30日及预期完整快照 |
| `源代码/demo-simulation.js` | 网页适配：原存档、六部、朝堂、人物、UI 和规则之间同步 |
| `Godot移植/realm_store.gd` | Godot JSON 读取、快照校验、保存、发出命令与快照信号 |

状态只含字典、列表、字符串、布尔与数值；人物和地方均用稳定 ID，不保存 DOM、闭包或场景节点。所有随机选择均由存档 seed、人物 ID、日序共同计算。游览界面不调用推进函数，不重掷人物状态。

## 规则接口

```js
const state = RealmSim.create(input, tables);
RealmSim.command(state, {
  id: 'project-001', tick: state.tick, type: 'project',
  region: 'jiangnan', project: 'canal', actor: 'xu'
}, tables);
RealmSim.advance(state, state.tick + 30, tables);
const history = RealmSim.annals(state, Math.floor(state.tick / 360));
```

`tick = 月序 × 30 + 日 - 1`，景和元年三月一日为60。推进只接受单调递增整数，离线时间不自动流逝。命令返回 `{ok, reason? , event?}`，失败不得扣除钱粮；相同成功命令 ID 不得重复生效。调用者还须校验每日精力、当前页面、旅行状态与身份权限，规则层负责钱粮、工期、资格和去重。

`advance` 逐日处理税粮、军粮、俸饷、地方发展、工程、人物日程与往来。网页月末只汇总经营日账，不重复征收、发薪或重演一天。旧版国库、粮仓、八地基础指标在调用前同步进规则，成功后一次性回写。工程、新增流民、粮价、关系记忆以经营状态为准。

## 接入 Godot 的顺序

1. 把配表、schema、port-vectors 和 `realm_store.gd` 放入项目。JSON 可直接用 Godot 的 JSON 解析能力读取，无需转换为表格插件。
2. 先将 `realm-core.js` 的规则逐函数译成 GDScript。JS 的 hash 使用无符号32位 FNV-1a；移植时在每次乘法后按 `0xffffffff` 截断，本版随机选择使用的稳定 ID 均为 ASCII；扩展到非 BMP 字符时须统一 JS 与 GDScript 的字符取值规则。不能改成引擎默认 hash，否则旧种子的日程会变。
3. 每次命令后把完整字典快照交给 `apply_snapshot`。连接 `command_requested` 到规则服务，连接 `snapshot_changed` 到 Control 场景；UI 只读取状态、提交命令。
4. 以 `port-vectors.json` 验证第30日结果逐字段一致，再接入差事面板与地方景象。这里只提供 JavaScript 规则验证，没有声称 GDScript 已通过同一测试。
5. 再迁移尚在网页适配层的旧朝堂、恋爱、选秀、家族、继承、许案等系统。它们仍是现有 JS 玩法，不能把经营内核文件等同于整部游戏已经彻底解耦。
6. 游戏中「这一年的记事」里的「下载经营记录」可生成独立 JSON；完整旧游戏存档仍从记事页的「导出存档」取得，两者用途不同。
